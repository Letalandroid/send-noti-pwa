Comparativa de Proveedores Push a Coste $0

Análisis completo de alternativas gratuitas para enviar notificaciones Web Push a iOS (iPhone) y Android.

RECOMENDADO ($0 DE POR VIDA)

1. Web Push Nativo (VAPID)

El estándar oficial W3C que utiliza este proyecto.

  • Coste: $0.00 / Ilimitado de por vida. Sin intermediarios, sin límites de usuarios ni de mensajes.
  • Cómo funciona: Tu servidor (o función serverless) envía peticiones HTTPS directas a los servidores de Apple (APNs: web.push.apple.com) y Google (FCM). Solo necesitas un par de claves criptográficas VAPID.
  • iOS PWA: Soporte nativo oficial desde iOS 16.4 sin pagar la cuenta de Apple Developer ($99/año).
  • Ventajas: 100% privado, máximo rendimiento, sin SDKs pesados de terceros, sin riesgo de que cambien los planes de pago.

2. Supabase (PostgreSQL + Edge Functions)

¿Se puede lograr el mismo resultado? SÍ, absolutamente.

  • Coste: $0 en su Free Tier (500 MB base de datos, 50,000 Edge Functions/mes, autenticación y webhooks incluidos).
  • Cómo funciona: Almacenas la suscripción push en una tabla Postgres en Supabase. Cuando desees enviar una notificación (manual, por cron o por un Trigger en la base de datos), invocas una Supabase Edge Function (Deno) que ejecuta el envío Web Push con tus claves VAPID.
  • Ventajas: Si ya usas Supabase para tu base de datos o autenticación, tienes todo unificado sin contratar ningún otro servicio.

3. Firebase Cloud Messaging (FCM)

El servicio tradicional de Google.

  • Coste: $0 (Envío ilimitado en el plan Spark gratuito de Firebase).
  • Cómo funciona: Requiere crear un proyecto en Google Cloud / Firebase Console, registrar la web app, e importar el SDK firebase/messaging.
  • Contras en iOS: Mayor complejidad de integración con el Service Worker en Safari iOS y peso extra de librerías JS comparado con el estándar VAPID nativo.

4. OneSignal

Proveedor comercial con panel web visual.

  • Coste: Gratuito hasta 10,000 suscriptores (con limitaciones en funciones avanzadas). Planes de pago costosos después.
  • Ventajas: Panel visual de marketing, segmentación y programación horaria.
  • Contras: No es 100% abierto; dependes de un proveedor comercial que puede limitar su plan gratuito en cualquier momento.

Implementación con Supabase a Coste $0

Si prefieres que la base de datos y el backend se alojen en Supabase, sigue esta arquitectura lista para usar:

1

Crear la tabla en Supabase SQL Editor

Guarda las suscripciones de los iPhones y dispositivos:

-- Tabla de suscripciones Push
CREATE TABLE push_subscriptions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  endpoint TEXT NOT NULL UNIQUE,
  p256dh TEXT NOT NULL,
  auth TEXT NOT NULL,
  device_type TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
2

Supabase Edge Function para enviar

Crea una Edge Function en Deno (carpeta supabase/edge-function.ts en este proyecto) usando web-push:

// En supabase/functions/send-push/index.ts
import { serve } from "https://deno.land/std@0.168.0/http/server.ts";
import webpush from "npm:web-push@3.6.7";

webpush.setVapidDetails(
  Deno.env.get("VAPID_SUBJECT")!,
  Deno.env.get("VAPID_PUBLIC_KEY")!,
  Deno.env.get("VAPID_PRIVATE_KEY")!
);

serve(async (req) => {
  const { title, body, subscription } = await req.json();
  await webpush.sendNotification(subscription, JSON.stringify({ title, body }));
  return new Response(JSON.stringify({ success: true }), { headers: { "Content-Type": "application/json" } });
});
3

Configurar Variables de Entorno en Supabase

En el panel de Supabase > Edge Functions > Secrets, agrega:

  • VAPID_PUBLIC_KEY
  • VAPID_PRIVATE_KEY
  • VAPID_SUBJECT (ej: mailto:tu@correo.com)
